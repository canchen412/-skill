（注意：同一 rate 下短稿的实际字/秒会偏高，因为标点停顿占比小 —— 用长稿测才准。）

**两个附带结论（都先用 ffprobe 量过，不靠估）：**
1. **云端合成是确定性可复现的** —— `bailian` 音色两次独立调用（C2 / A3）时长**完全相同：33.628s**。
   同文本 + 同音色 + 同 rate → 出同样音频。返工重跑不会「每次都不一样」。
2. **音色本身会带节奏差** —— `candi` 34.50s vs `bailian` 33.63s，差 **0.87 秒（+2.6%）**，
   来自音色（candi 念得稍缓），不是随机抖动。**换音色后要重新量一次节奏**，别照抄上一个音色的数。

## 四、逐字时间戳（可用）

`word_timestamp_enabled: true` → `payload.output.sentence.words`
248 字稿拿到 **242 个词**，逐字 ms 时间：

```
末词 慌@32974ms，音频总长 33.63s
首词 一@0ms→72ms，天@72→218ms，几@290→363ms   （词间空隙即停顿）
```

自动产出的 `.srt`（29 行，按标点聚合，不是一行一字）：
```
1
00:00:00,000 --> 00:00:01,090
一天几毛钱的肌酸，

2
00:00:01,090 --> 00:00:02,327
为什么还有人买贵了？
```

**这就能替掉本地那两步「whisper 逐字转写 + 拼音强制对齐」**（`vo_fixed.json` 里现在是 `pinyin-aligned`）。

## 五、文本规范化（自动发生，做字幕必须知道）

云端 TTS 送进去的不是原文，是它自己转写过的文本。实测到的**三类**（2026-10-16）：

| 原文 | 云端转写 | 字数变化 | 影响 |
|---|---|---|---|
| `19块9` | `十九块九` | 3 → 5 | 读法正确，**不用写 `pronunciation_dict`** |
| `99.9%` | `百分之九十九点九` | 5 → 8 | 百分号前置「百分之」，小数点读「点」 |
| `SGS` | `sgs` | 3 → 3 | 仅大小写；但**孤立的 `A` 却保留大写**（云端自己不一致） |

两个直接后果：
1. `words[].begin_index` 是按**规范化后**文本计的，**拿原文案去索引会错位**。
2. 想用逐字时间戳做字幕，必须先把原文做**同样的规范化**再对齐 —— 见 `scripts/mk_tokens_cloud.py` 的 `normalize()`。

读法实测无误（听感需他本人确认）：`19块9`→「十九块九」、`50多万`→「五十多万」、`SGS`→ 按字母读。

### 8.3 写脚本时踩到的三个坑（已修）

1. **标点判定必须逐字符** —— 云端会把标点和字母凑成一个词元（实测到 `，sgs`），按整词元判标点会漏掉夹在中间的逗号。
2. **百分号必须先处理** —— 顺序反了会生成错位的「九十九点九百分之」。正确：先 `(\d+(\.\d+)?)%` → `百分之+中文数字`，再处理裸数字。
3. **比较时统一小写** —— 云端对 `SGS` 转小写却把 `A` 留成大写，不统一；统一小写后长稿相似度从 0.9932 提到 1.0000（大小写不改变字符数，位置映射依然正确）。

| 位置 | 改法 |
|---|---|
| CLI | 新增 `--tts-engine auto\|cloud\|local`，**默认 auto** |
| 第 2 步 | `tts_cloud()`：`cloud_cosyvoice_ws.py` 整段合成 → `mk_tokens_cloud --check` 对齐闸 → `mk_tokens_cloud` 出四件套 → 必读词校验 |

| 回退 | `auto` 探测不到脚本/Key ⇒ **大声告警**后 local；显式 `cloud` 缺条件 ⇒ 直接报错（不静默降级） |

**实测（158 字稿，7 镜，同一台 8GB 机器）**：

- 第 1+2 步合起来 **10 秒**（`--tts-only` 实测：切镜 1s + 云端合成 9s）。
- 对齐 **1.0000**，零未映射字符（`160 词元 / 原文 142 字去标点`）。
- `durations.json` 7 句 = 镜数，`len(durs)==n` 断言通过；轮播切点读 `durs[定场句镜]["end"]` = 4.00s。
- `vo.wav` 20.93s（末字 end 20.29s）；`shot_bounds` 首镜 `[0,4.0]`、末镜 `[19.272,20.29]`。
- **下游兼容闸**：拿这份云端 token 直接跑 `build_ad_video` → 底片渲染成功（21.39s），**没有出现「口播字数≠文案字数」警告**（token 字数 140 == phrases 字数 140）。
- 必读词校验改走**云端逐字实测稿**（`vo.words.json` 拼接后按同一套 `normalize` 比对），比 F5 那套 whisper ASR 复判更硬、零额外耗时。

**回退分支也验过**：`auto` 在把 Key 拿掉后打印告警并返回 `local`；显式 `cloud` 保持 `cloud`（交给后续报错，不静默降级）；`local` 原样。

**为什么第 2 步里 `tail_keep` 用默认 1.0**：云端镜内 token 是逐字实测，末 token 就收到末字结束；F5 版的 0.88 留白是「按字数比例猜」时代的防压音尾手段，云端不必照搬。
