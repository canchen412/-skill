## 一、★这套音效的独特价值：按「叙事节奏」分类，不按「音色」

原视频的剪辑时间线用**红标**分了 15 个**叙事节点分类**，这正是它比普通音效包强的地方——
普通音效包按材质分（金属/玻璃/冲击），这套按**「什么时候用」**分，拿来就能对上口播的每一句。

**完整分类链（红标，从左到右＝叙事推进顺序）**：

```
开场钩子 → 悬疑开幕 → 提出问题 → 能量点 → 产生疑问 → 突然转折
→ 积极爆发 → 高潮迭起 → 循序渐进/倒计时 →噗噗 → 噗噗
→ 揭秘 → 天光一现 → 放大 → 恍然大悟
```

## 三、按口播节奏排的「使用地图」

照着一条带货口播的叙事顺序排，直接照抄位置：

| 口播阶段 | 建议音效 | 理由 |
|---|---|---|
| 开头钩子（第一句抛出） | **01 开场闪光转场** | 高频闪一下抓注意力 |
| 制造疑问 / 抛问题 | **03 短促疑问音** | 问句配上扬感 |
| 痛点陈述、逐条列举 | **09 秒针倒计时** | 滴答＝时间在走，配合「3 个原因」 |
| 强调产品 / 数据 / 成分 | **02 叮叮叮** 或 **07短促金属敲** | 逐字点缀，跟关键词卡点 |
| 转折句（从痛点转到方案） | **06 疾速机器滑音** 或 **04 综艺哗** | 滑音做转场；哗声做「众人反应」 |
| before/after 对比揭晓 | **08 沉重心跳** ★ | 全场最重的重锤 |
| 效果揭示、真相出来 | **10 震惊闷响** ★ | 闷雷式反转 |
| 顿悟 / 原理讲透 | **12 天光一现** ★ | 最亮一下＝「原来如此」 |
| 力量 / 训练高潮段 | **13 力量迸发渐强** | 渐强铺垫后爆发 |
| 片尾 CTA 收尾 | **14 恍然大悟** ★ | 3.1s 长收束，落幅用 |

**保留不动、别浪费的三张王牌**：`08 沉重心跳`、`10 震惊闷响`、`14 恍然大悟`——
这三个是「重锤型」音效，一条 40 秒的片用1~2 个就够，**用滥就没有分量了**。

## 四、怎么用（与现有渲染器对接）

这批音效放在 `<技能库>/koubo-ad-video/assets/sfx/爆款叙事音效_261008/`（**子目录**，不覆盖原有 28 个音效）。

> ★**关键**：渲染器的 `SFX_DIR` 是**平铺**的（`build_ad_video.py:156`），
> `sfx_files` 的「值」会被 `os.path.join(SFX_DIR, 值)` 直接拼接，
> **不支持写 `子目录/xxx.wav`** ⇒ 这批音效必须**在 config 里用 `sfx_files` 显式映射到带子目录的路径**。

**用法一：`trigger_sfx`（纯音效触发词，不弹字）** —— 见 SKILL 决策表 #42b / #98。
**必须先在 config 顶层声明 `sfx_files`**，把短名映射到实际路径，然后 `trigger_sfx` 里用短名：

```jsonc
{
  // ① 顶层映射：短名 → 实际路径（值可带子目录，这里才允许斜杠）
  "sfx_files": {
    "narr_flash":  "爆款叙事音效_261008/01_开场闪光转场.wav",
    "narr_ding":   "爆款叙事音效_261008/02_叮叮叮_清脆点缀.wav",
    "narr_thump":  "爆款叙事音效_261008/08_沉心情跳_低频重击.wav",
    "narr_shock":  "爆款叙事音效_261008/10_震惊闷响.wav",
    "narr_light":  "爆款叙事音效_261008/12_天光一现_高频闪.wav",
    "narr_final":  "爆款叙事音效_261008/14_恍然大悟_收束.wav"
  },
  // ② 再用短名触发（渲染器按 sfx_files[短名] 找文件，找不到会打印「不在音效池」并跳过，不会崩）
  "trigger_sfx": [
    {"phrase": 2,  "kw": "今天",   "sfx": "narr_flash"},
    {"phrase": 8,  "kw": "烟酰胺", "sfx": "narr_thump"},
    {"phrase": 16, "kw": "高含量", "sfx": "narr_light"},
    {"phrase": 22, "kw": "个位数", "sfx": "narr_final"}
  ]
}
```

> ⚠️ 上例 `narr_thump` 的路径我写错了一个字（应为「沉重」），实际配置请照第二节表格里的**真实文件名**写。
> 渲染器的兜底很安全：**`sfx_files` 里找不到文件只会打印警告并跳过**（`build_ad_video.py:946` 的 `sfx_avail` 过滤），不会崩片。

**用法二：直接拖进剪映** —— 都是标准 44.1kHz 单声道 wav，命名已带用途与编号，可直接拖到时间线。

### 混音建议（沿用现有渲染器口径）

- 峰值已归一到**−3 dBFS**，可直接进渲染器的 `alimiter` 兜底链，不会削波。
- 现有渲染器有 `sfx_policy`（邻避→合并→密度）做**去重/避让**；这套里 01/02/03/05/07/11/12 都是**短促型**，
  天然容易被密集触发 ⇒ **同一镜内不要堆两个短促型**，让 `sfx_policy` 的邻避规则生效。
- `narr_thump`/`narr_shock`/`narr_final` 是**低频重锤型**，与 `kw_boom`（重点字重击）功能重叠
  ⇒ **同一个镜不要同时用**，否则两声叠在一起会糊。

## 五、提取方法（可复用于同类音效分享视频）

```bash
# 1) 分离音轨 + 归一化单声道
ffmpeg -i src.mp4 -vn -ac 1 -ar 44100 -c:a pcm_s16le audio.wav

# 2) 短时能量包络（20ms hop / 40ms win）+ 静音门限切分，合并间隔 < 0.12s
#    门限 = max(底噪×2.5, 峰值×0.06)
# 3) 每个事件切出（前后各留 30~50ms 余量，避免削掉起音）
# 4) 5ms 淡入淡出去爆音 + 峰值归一到 -3 dBFS
# 5) 高通 110Hz 去 BGM 低频隆隆（★实测不影响音效主体：
#    08 沉重心跳 低频占比 48.5%→48.6%，10 震惊闷响 25%→22.2%，主体完整）
```

**对齐到画面时间线的技巧**（本次关键手法）：
时间线横向滚动速度 ≈ 1:1（实测#01@0.37s 对应时间线 00:00，#02@1.29s 播放头右移约 1 秒），
所以**取每个音效事件起点 +0.05s 抽帧**，画面上的播放头位置即该音效在时间线上的落点，
可据此读出它归属哪个分类标签。

## 六、⚠️ 已知局限

1. **原视频只有 320×568 竖屏**，时间线标签文字靠**目视 + 增强**读取（OCR 读数不可用，源分辨率太低）。
   个别标签为**推断补全**（如 `03/07/11/12` 在画面上未直接读到完整标签，是按其所在红标节点归类），
   但**不影响可用性** —— 文件名与频谱特征已自洽。
2. 原片无人声讲解（已用 whisper 确认：全片仅识别到画面水印文字），故切出的音效**不含人声**，
   也**未混入 BGM**（处理前后频谱对比证实）。
3. `06疾速机器滑音`（2.18s）与 `14 恍然大悟`（3.11s）偏长，用时建议**裁短或做淡出**，
   否则会压住口播人声。
