# 流程优化：一次集中确认（2026-09-27 灿爹拍板）

> 灿爹原话要点：
> ①「每次生成的图片与分镜文案匹配度不高……**先输出一张「分镜—文案—素材」对应表**，我逐条确认或提出修改意见，**通过后你再生成图片和素材**。」
> ②「**正式生成前只做一次集中确认**，可多轮修改直到我确认通过，**确认后一次性执行到底，不再中途反复打断**。」

---

## 一、现有流程与问题点

| # | 环节 | 产物 | 依赖 | 当前瓶颈 / 问题点 | 返工代价 |
|---|---|---|---|---|---|
| 0 | 合规扫描 | 红线改写清单 | 文案 | ✅ 已有闸门（§0） | 低 |
| 0.1 | 错别字/语义核验 | 疑点选项 | 文案 | ✅ 已有闸门（§0.1） | 低 |
| 1 | 产品图定位 | 产品白底图 | 品牌名 | 多产品线偶发选错；需逐张目视 | 中 |
| 2 | 配音 + 转写对齐 | vo.mp3 / vo_fixed.json | 文案 | CPU 约 7 分钟（不等人）；数字中文读法需二次修正 | 中 |
| 3 | **分镜规划** | 镜数 + 时长 | 逐句时长 | ⚠️ 配额有脚本，但**配图在规划后直接落地**，缺「先给人看」环节 | 高 |
| 4 | **配图 / 生图** | 分镜图 | 分镜 + 图库 | ❌ **最大瓶颈**：语义对不上、连续同图、他品入镜、五官长出、构图出框，全部成片后才发现 | 最高（烧积分 + 重渲） |
| 5 | 写 config | config.json | 素材 + 时间轴 | 重点字/卡片落位靠人工，易漏 | 中 |
| 6 | 渲染 + 质检 | 成片 mp4 | config | 渲染 40–48s 不慢；慢的是**渲染后逐镜发现素材问题 → 改图 → 再渲** | 高 |
| 7 | 交付/定版 | 标题 + 话题 | 成片 | ⚠️ 用户在此才第一次看到完整画面，前面判断全是我单方面做的 | 高 |

**根因三条**
1. **素材决策没有事前可视化**——图选得对不对，只有成片出来才看得见。
2. **确认点碎**——合规、积分、换图建议、配音读法、重点字位置分散在全流程，一轮打断 5–8 次。
3. **图库复用靠我在脑子里匹配**（§0.2 已立规矩），但没有摊开给用户核。

## 二、优化后流程（P0–P5）

| 阶段 | 做什么 | 输入 | 输出 | 确认 |
|---|---|---|---|---|
| **P0 文案闸门** | 合规扫描 + 错别字/语义核验（§0 / §0.1） | 用户文案 | 红线清单 / 疑点选项 | 🟡 **仅当有问题时**（无问题直接过） |
| **P1 配音对齐** | CosyVoice3 → whisper small → align_vo → 逐句时长 | 定稿文案 | vo.mp3、vo_fixed.json、逐句时长 | ❌ 不打断（数字中文读法按铁律自动处理） |
| **P2 分镜 + 配图规划** | 按时长配额定镜数 → 全库语义匹配（§0.2）→ 复用/实拍/补生分类 → 自动自检 | 逐句时长 + 图库清单 | **《分镜—文案—素材对应表》** | ❌ 出表不打断 |
| **P3 集中确认** | 用户逐镜批注（通过/换图/新生成/合并/删），可多轮改到通过 | 对应表 | 批注 JSON / 变更清单 | 🔴 **唯一必经确认点**（积分预估一起批） |
| **P4 一次执行到底** | 补生图（并行）→ P 图修复 → 写 config → 渲染 → 质检 → 归档 | 通过的对应表 | 成片 mp4 + 质检报告 | ❌ 全程不打断 |
| **P5 验收** | 成片 + 标题话题 + 图库扩充建议 | 成片 | 定版 / 微调清单 | 🟢 只验收，不重复决策 |

**硬规矩**
- P3 未通过前：**一张图都不生成、一次渲染都不跑**。
- P3 通过后：**中途不再打断**，直到成片交付（含积分已在 P3 一次性点头）。
- 每轮复审只重出「被改动的那几镜」，不整表重出。

## 三、每轮确认的输入 / 输出

| 轮次 | 触发 | 我给的（输入） | 你给的（输出） | 通过标准 |
|---|---|---|---|---|
| 第 0 轮 文案核验 | 发现错别字/语义不通/合规红线 | 原句 + N 个改法选项 | 选一个（或「不改」） | 文案定稿、无红线 |
| **第 1 轮 对应表集中确认** | 每次出片必经 | 对应表（画面描述 / 素材 / 自检结论 / 积分预估） | 逐镜批注 + 文字意见 | ❌ 清零、⚠️ 有处置说明、补生图积分已点头 |
| 第 2…N 轮 修订复审 | 上一轮有未通过项 | 只重出被改动的镜 + 改动说明 | 对改动项再批注 | 同上，循环至全通过 |
| 最后 1 轮 成片验收 | 渲染完成 | 成片 + 质检结论 + 标题话题 | 「定版」或微调清单 | 定版即归档 |

## 四、对应表字段与自检规则

**表字段**：镜号 ｜ 时间区间/时长 ｜ 文案原文 ｜ 画面描述（人物/场景/动作/镜头运动）｜ 素材来源 ｜ 素材文件 ｜ 匹配度自检 ｜ 决策 ｜ 批注

**自动自检（脚本跑，0 积分）**

| 项 | 判据 | 等级 |
|---|---|---|
| 时长合规 | 引用 `shot_plan.py` 的 `judge()`（图片镜下限 / 视频镜下限 / 软上限 / 宣言镜） | ❌ 闪屏必改、⚠️ 偏长偏短 |
| 素材存在 | src 文件不存在 | ❌ |
| 一镜一图 | 与上一镜同图 / 与隔一镜同图 | ❌ / ⚠️ |
| 他品污染 | 素材名含他牌关键词（米当卡/三角喵/诺特兰德…），**需 Read 目视复核** | ❌ |
| 产品镜 | 文案点到品牌/品类但素材名不像产品合成图 | ⚠️ |
| 重点字 | 黑板宣言镜及之前出现 keywords（#42）；keywords 未给 pos（大字压主体） | ❌ / ⚠️ |
| 动效 | 静图超软上限且无 motion | ⚠️（建议加缓动或拆） |

**脚本判不了、必须我 Read 目视的三项**：构图（主体出框/贴底）、五官（无脸 IP 长出鼻嘴）、他品入镜。→ 目视结论写进该镜自检说明。

## 五、脚本用法（`scripts/storyboard_match.py`）

```bash
S=~/.workbuddy/skills/koubo-ad-video/scripts/storyboard_match.py
P=/Users/mac/.workbuddy/binaries/python/versions/3.13.12/bin/python3

# ① 出可批注 HTML（主交付物，浏览器打开逐条批注 + 导出批注 JSON）
cd 工程目录 && $P $S --config s1/config.json --brand 21金维他 --html 对应表.html

# ② 纯文本版（贴对话快速过目） / ③ CSV（表格软件对照）
$P $S --config s1/config.json --md
$P $S --config s1/config.json --csv plan.csv

# ④ 回填批注 → 打印「待执行变更清单」
$P $S --config s1/config.json --apply annotations.json

# 可选：人工覆盖画面描述 --desc desc.json {"3":"小绿人指着满桌肉"}；表头说明 --note "……"
```

- 时长阈值**直接 import `shot_plan.py`**，那边改规则这边自动同步，不复制常数。
- 待补生成的镜：config 里 src 写 `NEW:画面要点` → 表内自动标「待补生成（≈5–10 积分/张）」并计入 P3 的积分预估。
- `--apply` 输出「换图 / 新生成 / 改描述 / 合并 / 删除 / 通过」分组清单；**只要还有未通过项就不允许进入 P4**。
