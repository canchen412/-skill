# 片头卷播横幅 (Conveyor Banner)

黑底 + 竖卡列高速横向卷动 + 固定白框取景窗 + 双色字幕 + 收尾主图放大。
用于「价格钩子」镜，把一句价格文案配一串训练图做漫威式轮播。

工具：`scripts/opening_banner.py`

## 复刻来源

从参考教程 `ref.mp4`（568×320, 30fps, 117s）逐帧反推，比例 1920/568 = 3.3803。

## ★★★ 铁律三：卷播必须**全程渐慢**

> 「前面开头还是太快，开始是这个速度，但是越后面越慢直到0，
> 用一个让人适应的舒服的变慢过程」（2026-10-06）

**不要**「前段恒速 + 末尾突然减速」——前 2.4 秒速度完全不变 ⇒ 观感就是「太快」。

```python
def ease_in_out_cubic(u):
    u = min(1.0, max(0.0, u))
    return 4.0*u*u*u if u < 0.5 else 1.0 - ((-2.0*u+2.0)**3)/2.0

if fi < NFF:
    u = fi / max(1, NFF - 1)
    off += v1 * (1.0 - ease_in_out_cubic(u))     # 速度 1→0 一路平滑
else:
    off += v_hold                # 段3 背景继续缓慢转
```
实测（v1=95、focus-at 2.42s / 72 帧）：
`95 → 94 → 90 → 79 → 58 → 30 → 12 → 3 → 0`px/帧

### 「更慢」的调参三杠杆
| 杠杆 | 参数 | 效果 |
|---|---|---|
| ① 初速降（首选） | `--v1` | 整体等比例变慢，曲线形状不变；卡数会变少 |
| ② 减速段拉长 | `--focus-at` | 末段拖更久；⚠️ 会压缩段3，需同步 `--dur` |
| ③ 定格加长 | `--dur`+`extend` | 大图多停一会儿；⚠️ 须与 ② 联动 |

肌酸实测：`v1 95→70` + `focus-at 2.42→2.80` + `dur 4.12→4.40` + `extend 1.00→1.28`
⇒ 曲线 `77→64→43→25→14→7→0`，卷 5.9 张卡。

### ★ 总位移必须用数值积分 Σf，不能乘秒数
```python
_sumf = sum(1.0 - ease_in_out_cubic(i/max(1,NFF-1)) for i in range(NFF-1))
off_est = v1 * _sumf            # ✅ v1 是「每帧位移」
# ❌ v1 * (NFF/FPS) * 0.5       把「每帧位移」当「每秒速度」，少一半
```
Σf=36.0（v1=95/NFF=72）⇒ 3420px = 6.8 张卡。
`off_stop = min([k*PITCH...], key=lambda o: abs(o-off_est))` 保证停住时卡贴白框。

### 隐蔽 bug：`if/else` 缩进错乱会覆盖 t1/t3
`if rip_cx is None: rip_cx = W/2.0` 后面若接 `else:` 却缩进在 `if` 块内，
`else` 里的 `t1/t3` 赋值会执行，**focus-at 直接失效**（表现为恒速不减速）。

### 配比（肌酸实测）
`--v1 95` `--focus-at 2.42` `--dur 4.12` `--an-dur 1.10` `--shake-k 1.5`
⇒ 段3 定格 1.70s + config `extend: 1.0` ⇒ 大图实际停留 **1.8s**

## ★★★ 铁律一：主图必须是卡列的**最后一张**

灿爹原话（2026-10-06 拍板，**跨项目长期有效**）：
> 「跳出来的主图其实就是小白框框到的最后一个图片，这样子看起来才协调。
> 以后如果我要生成视频，你也要先确定主图，然后它是最后一个框到的，
> 然后再跳出主图的 16:9 的完整的图片，这样子效果才好。」

**代码已强制**（`scripts/opening_banner.py`）：`hero = n - 1`，不接受手动指定。
```python
hero = n - 1      # ★ 卡列最后一张 = 主图（不是 hero = 0）
x0 = (hero + 0.5) * PITCH - box_cx - off_stop
```

### 生成流程（以后每次照此执行，别问第二遍）
1. **先确定主图** —— 优先问灿爹要文件名；没指定就从图库 16:9 完整图里挑
   （筛选：`cv2.imread` 后 `abs(w/h - 16/9) < 0.02`，小绿人图库有 70 张）
2. 把主图放到**卡列最后一个位置**（`cards.txt` 最后一行）
3. `--hero-src` 指向**同一个文件**：
   - 段2 白框框住它的**竖卡裁切版**
   - 段3 跳出它的**完整 16:9 版**
4. 卡数 = `段1 滚动量 / PITCH + 2`（主图已在列内，不额外占位）

### 渲染时必看自检输出
```
段2 末白框中心显示 imgs[15]，卡心偏移 +0.0px（应=0）
→ 段3 放大的就是这一张：imgs[15] = 展示_暗场出拳能量爆炸_全景.png
✓ 主图一致：卡列最后一张 == --hero-src
```
文件名不同会打 `⚠️ 主图内容可能不一致` —— **必须改正后再交付**，
否则「框住的」和「跳出的」不是同一张，观感不协调。

⚠️ 段2 是主图的竖卡裁切版、段3 是完整 16:9 版，
这个「先裁切、再完整」的过程本身就是视觉连续性的来源，**不要改成同一尺寸**。

## ★ 速度结构（灿爹最终拍板，3.00s 基准）

用**分句配音实测**拿到真实时间点，再按语义边界切：

| 时间 | 配音内容 | 画面 |
|---|---|---|
| 0 → 1.64s | 「19块9承包你3个月的健身成本」 | **恒速卷播**（`--v1`，默认 95px/帧） |
| 1.64 → **2.72s** | 「今天我们讲」 | **速度线性降到 0**（减速段 1.08s，灿爹要求加长） |
| **2.72s** | 「肌酸」尾音 | 框中卡 **连续放大 1.30×** + **白边相框** + **金属咔哒** |

⚠️ 减速段别只按配音的语义边界切。配音「肌酸」在 2.48s 起，
但速度要更早、更缓地收完才好看 → `--focus-at 2.72` 兼顾两者。

`REF_SEG = (1.64, 0.84)`（段1、段2 时长，合计 2.48s 到定格）。

### 段1 速度 `--v1`：以「看得清」为准

教程原版 **156px/帧太快看不清**（每帧移动 1/3 个卡宽）。
默认降到 **95px/帧**（慢 39%），实测每张卡能停 5 帧以上。
嫌快就调小：`--v1 75`。

### 段2 线性减速到 0
```python
u = (fi - NF1) / (NFF - NF1)
cur = v1 * (1.0 - u)      # 速度线性衰减，末帧为 0
off += cur
```
实测曲线：95 → 91 → 72 → 53 → 34 → 15 → **0**，平滑无突跳。

### 时间轴缩放 `KS = dur / 3.00`
3.00s 是标定基准（时间点来自分句实测）。短版/长版按 `KS` 缩放。
⚠️ `--focus-at` 是**实测绝对秒数**，不要再乘 `KS`（会双重缩放）。
⚠️ 段1 结束要 `t1 = min(t1, t3*0.90)`，保证减速段不为空。

## ★★ 「框住哪张 → 放大哪张」必须同卡（灿爹两次强调）

段3 放大的**必须就是白框里那张**，不能另指定一张跳出来。
`--hero` 作废，改为**自动求解**。

### 几何推导
```
卡 hero 中心屏幕位 = x0 + hero*PITCH + PITCH/2 + off_stop
要它 == box_cx  ⟹  x0 = box_cx - hero*PITCH - PITCH/2 - off_stop
```
⚠️ 旧写法 `x0 = box_cx - (hero+0.5)*PITCH` **漏了 `off_stop`**，
结果卡心偏移正好等于 `off_stop`（6000px），整张卡错位、段3 画出来的
和框里看到的不是同一张。

### 选停止位移：必须是节距整数倍
`off_stop ≡ 0 (mod PITCH)` 卡才严丝合缝对正框心。
在整数倍候选里挑**段2 峰值速度最接近 v1** 的那个，段1→段2 衔接才不突降：
```python
off1 = v1 * NF1
cands = [k*PITCH for k in range(1, 40) if k*PITCH > off1]
off_stop = max(cands, key=lambda o: -abs(2.0*(o-off1)/n2 - v1))
off2 = off_stop - off1
v2_peak = 2.0 * off2 / n2      # 三角形面积关系：线性收零的峰值
```
实测 v1=95 时选中 `off_stop=6000`（12 节距），`v2_peak=107.6` → 0，衔接自然。

### 放大倍数上限
1.30× 会超画面高度（`800×1.3=1040`），被夹紧后只剩 0.765×（等于没放大）。
**用 1.16×**（800→869px），配合 `max_oh=H-180`、`max_ow=W-300`。

## ★ 齿轮卷播音效（`scripts/opening_banner_gear.py`）

**齿轮转速必须跟随画面速度实时变化**——快时「咯咯咯吱」密，减速时同步变疏。

### 核心：用「累计齿相位」触发，不能逐帧独立判断
```python
teeth_per_card = 4
phase = 0.0
for fi in range(NFF+1):
    v = 速度(fi)                                  # 与画面速度曲线完全一致
    if v < 0.5: continue
    dteeth = v / PITCH * teeth_per_card            # 齿/帧
    prev = phase; phase += dteeth
    if int(phase) - int(prev) >= 1:                # 跨过整数 → 发一齿
        发齿音(音高=1400+1000*v/v1, 音量∝√(v/v1))
```
❌ 逐帧独立 `if phase < rate` 会在减速段几乎不发声（实测只有 8 个瞬态）。
累加相位才能做到「速度降 → 齿变稀」。

实测 48 齿，间隔 `0.033s → 0.067s → 0.100s → 0.133s` 渐疏。

### ★★ 齿音 = 老收音机金属旋钮的「哒哒」（灿爹要质感，返工两次）

**两次返工的教训**：
1. 第一版 1400–2400Hz + 48ms → 「电子高频咔哒」，廉价
2. 第二版照教程实测改成 **180Hz 低频 + 125ms 长尾** → 像闷闷的嗡嗡，**也不对**

灿爹原话：「不是低频齿轮，是**老收音机上金属旋钮的哒哒**，很有质感」。

### ★★★ 最终配方（灿爹认可后按教程精读校准）

| 时刻 | 峰频 | 低(<300) | 中低(300-800) | 高(>1.5k) | 起振 | 衰减尾部 |
|---|---|---|---|---|---|---|
| 0.480s | 200/334/133/267 | 37% | 29% | 24% | 0.1ms | **10ms** |
| 0.540s | 200/133/334/267 | 63% | 23% | 9% | 0.0ms | 13ms |
| 0.570s | 200/133/267/400 | 40% | 17% | 41% | 0.0ms | 13ms |
| 0.630s | 200/133/267/400 | 29% | 22% | 42% | 0.0ms | 13ms |

**关键：200/267/334/400Hz 四层等间距金属簇**（不是单音），
起振 0.1ms，衰减尾部仅 10–13ms。

```python
CLUSTER = (200.0, 267.0, 334.0, 400.0)     # 四层金属簇
for i_, f0 in enumerate(CLUSTER):
    f = f0 * (1.0 + 0.14*spd)                # 速度↑音高↑
    amp = (0.62, 0.48, 0.34, 0.22)[i_]        # 高次递减
    x += amp * np.sin(2*np.pi*f*t)
x = x*0.90 + nz*0.16                          # 极短宽带咔（10抽头）
x += 0.07*sin(2π*3800t) + 0.045*sin(2π*6600t) + 0.025*sin(2π*10500t)  # 中高频同步升调
e = exp(-160t) + 0.28*exp(-400t)              # 尾部 ≈11ms
```

⚠️ **`tooth_len` 必须 > 衰减尾部**（取 30ms，不是 13ms），
否则信号被硬截断、听着像"被切掉"、测出来只有 3ms。
这是 v11「衰减 2ms 对不上教程」的根因。

校验：峰频 200/250/300/350Hz、低 33-34%、中低 28-30%，与教程一致。

### 定格：居中放大 + 遮罩压暗背景

**不要清成纯黑**（`img[:] = 0`），而是**压暗到 38%**：
```python
ov  = min(1.0, tsec/0.22)          # 0.22s 内压暗到位
dim = 1.0 - 0.62*ov
dark = (img*dim).astype(np.uint8)
m = 主卡外框区域 ±30px             # 该区域保持原样
img[mask区域] = dark[mask区域]
```
先压暗 → 再画白边相框 → 再嵌主卡，顺序不能反。

居中校验：`fx = (W - (cw+2*bdw))//2`，实测偏移 −1px ✓

### ★★★ 白框必须「贴住卡片」——用独立宽度参数必然歪（灿爹截图指出）

**症状**：定格时卡片看着歪、框内两侧露黑边。

**实测**：框内宽 441px、卡片 406px ⟹ 左右各多 17px 黑边 ⟹ 视觉「歪」。

**根因**：白框宽度是**独立参数**（`BOX_TGT = CARD_W + 44 = 450`），
与卡片在屏幕上的实际位置无关。卡片位置由 `PITCH` 决定，两者对不上。

**修法**：框宽由卡片实际尺寸推导，框心跟随卡片中心：
```python
bdw_t  = max(3, int(round(9 * (1.0 - 0.10*min(1.0, fi/NFF)))))
card_lx = int(round(box_cx - CARD_W/2.0))     # 由几何保证精确居中
box_cx_f = card_lx + CARD_W/2.0               # 白框中心跟随卡片
w_now   = CARD_W + 2*bdw_t                    # ★ 框宽 = 卡宽 + 两侧白边
bh      = CARD_H // 2                         # ★ 框高 = 卡高（别做比例推导）
cv2.rectangle(lay, (round(box_cx_f-hw), BOX_CY-bh),
                    (round(box_cx_f+hw), BOX_CY+bh), b, BOX_LW)
```
实测：框 434px = 卡 406 + 2×14px 白边，框心偏移 **0px** ✓

⚠️ 别再写 `int(BOX_H/2 * (w_now/BOX_W)**0.5)` —— 那会让框变矮 88px。

### 段3 放大起点必须 = 段2 末卡片实际尺寸（含白边）
否则白框消失那一刻会有跳变。白边起点也要对齐：
```python
bdw0 = max(3, int(round(9*(1.0-0.10))))       # = 8，与段2 末一致
bdw  = max(5, int(round(bdw0*(1.0+0.6*ease))))
```

### ★★ 定格音 = 三段式「机械锁定」，不能有二次起振（灿爹说"啾"）

**症状**：灿爹形容定格音「啾的一声」= 鸟叫。

**实测根因**：峰频 **2550Hz** + 包络 `0.44 → 0.01 → 0.34`
—— 高频 + 极快二次起振，正是动物叫声的调频特征。

**正解：三段式锁扣，单调衰减**
```python
# ① 咔哒 click：2ms 起振、18ms 衰减（清脆但短）
nz = convolve(randn(0.045*SR), ones(18)/18)
x[:cn] += nz * exp(-220*ct) * 0.50
# ② 锁定 thunk：190→120Hz 下滑低频，280ms 衰减（厚重的「到位」感）
fn  = linspace(190, 120, n); ph = 2π*cumsum(fn)/SR
x += (sin(ph) + 0.30*sin(2*ph)) * exp(-11*t) * 0.72
# ③ 金属余韵：1.1k/2.2k/3.3kHz 极短泛音
x += Σ amp*sin(2π*f*t)*exp(-38*t)
```
实测：峰频 **200/150/250Hz**（低频主导），
包络 `0.32 → 0.24 → 0.19 → 0.13 → 0.08 → 0.02` **单调衰减无二次峰**。

⚠️ 判定标准：**包络必须单调**。出现第二个峰 = 听着像"啾"。

### 混音平衡
齿轮比人声突出，音效要抬到 `--sfx-gain 0.50`、人声略降到 `--vo-gain 1.45`。

## ★ 段3：主卡「浮出」而非「独占」（灿爹拍板）

**不要 `img[:] = 0` 把背景清黑**——那样只剩一张卡悬在黑底上很难看。
正确做法：卡列**继续缓慢转动**，框中那张**浮在上层**放大。

```python
# ① 速度积分：段3 卡列不停
if fi < NF1:      off += v1                      # 恒速
elif fi < NFF:    off += v1*(1.0 - u)            # 线性减速到 0
else:             off += v_hold                  # 继续缓慢转（--v-hold，默认 7）

# ② 弹出动画：easeOutBack，末段轻微回弹像"跳出来"
u = min(1.0, tsec/0.52)
c1 = 1.70158
uu = u - 1.0
ease = 1.0 + (c1+1.0)*uu**3 + c1*uu**2 if u < 1 else 1.0
sc = 1.0 + 0.30*ease     # ★ 1.0→1.30（卡高 800→940）

# ③ 白边相框：先铺「比卡片大 bdw」的纯白实心矩形，再把卡片嵌进去
cv2.rectangle(img, (fx,fy), (fx+cw+2*bdw-1, fy+ch+2*bdw-1), (255,255,255), -1)
img[hy:hy+ch, hx:hx+cw] = hero_im     # hx=fx+bdw
```
❌ 千万别用 `cv2.rectangle(..., thickness=bdw)` 画外描边——会被随后绘制的
卡片**完全盖住**，白边等于没画。必须用实心矩形 + 内嵌。

### 投影的坑
环形投影挖空范围要覆盖**整个相框（含白边）**，只挖卡片区会让阴影
压在白边和卡面上，把主卡压暗。挖空用 `fy/fx` 起点、`+2*bdw` 尺寸。
主卡另加 `convertScaleAbs(alpha=1.10, beta=8)` 提亮，保证主体跳得出来。

### ★ 尺寸必须夹「卡高」而不是「外框高」
1.30× 时卡高 1040px > 1080-字幕带。若按外框夹紧会被压到 1.16×（等于没放大）。
**直接夹卡高**：
```python
MAX_CARD_H = 940
if ch > MAX_CARD_H: k = MAX_CARD_H/ch; ch, cw = int(ch*k), int(cw*k)
fy = max(0, int((H - ch - 2*bdw) * 0.40))   # ★ 位置偏上，底部只留给字幕 ~70px
```
实测：卡 476×940（1.30×）、外框 508×972、`fy=43`、底边 1015（画面 1080）。

## ★ 配音必须混进去（踩过的坑）

灿爹明确反馈「这句话没有声音」——**不是没音效，是没配音**。
之前只做了「画面 + 音效」，从未把 TTS 配音混进视频。

**用封装脚本，别手工 ffmpeg**：

```bash
python3 scripts/opening_banner_mux.py \
  --video gen/banner.mp4 \
  --vo vo/hook.wav \
  --sfx gen/sfx.wav \
  --out final.mp4 \
  --dur 3.00 --vo-gain 1.5 --sfx-gain 0.42
```

它做四件事：
1. **缺 `--vo` 直接报错退出**（防止再次漏配音）
2. 配音 `volume=1.5 + highpass=80`（去低频隆隆声），音效压到 `0.42` 防盖人声
3. `alimiter=limit=0.92` 防削波
4. **成品自检**：音轨峰值 / RMS / 分段静音洞 / 轨道齐备，任一不过就报错

⚠️ `-t <dur>` 而非 `-shortest`（音轨短几十毫秒会截掉视频末帧）。

## 用法
```bash
# 1) 合成音效（按目标时长自动缩放时间轴）

# 2) 合成到视频
```

# ★★ 接入成片：两条铁律（2026-10-06 血泪）

## 铁律一：卷播片段必须能带自己的音轨（`own_audio: true`）

**踩坑现象**：样片里卷播音效（突然加速到暂停）和定格咚都响得正好，
但接进正式成片后**一个都不响** —— 成片开头只有配音的人声。

**根因**：`build_ad_video.py` 的 `prod` 镜分支只写了 `[k:v]`（取画面），
片段自带的音轨被直接丢掉。成片混音链里只有全局 `vo.mp3` + 音效池 + BGM。

**修法**：镜位加 `own_audio: true`，渲染器会把该片段音轨接入，
并**自动把全局 vo 在同一区间静音**（否则双重人声）：

```json
{ "text": "3个月的健身成本只需要39块9，今天我们讲，肌酸。",
  "kind": "prod",
  "video": "gen/片头卷播_肌酸_定格咚.mp4",
  "src": [0.0, 4.4],
  "own_audio": true,
  "own_audio_gain": 1.0,
  "extend": 1.15 }
```

规则要点：
- 接入点固定 **素材 0s**（素材自带混音从 0s 就是完整一条，起手音效在 0.2s 前已响）。
  若跟着 `timeline.start`（约 0.20s）走会整体右移，与字幕错位。
- 素材比该镜短时（extend 让画面停在定格帧上），音轨**取满素材即止**，
  余下画面时长靠末帧静止撑住 —— 音轨跟着拖长只会取到素材末尾的静音。
- 全局 vo 的静音上界取「画面实际结束时刻」而非「音轨长度」，
  否则卷播结束后会冒出全局 vo 的人声。

## 铁律二：`extend` 不能与配音里的自然停顿重复计算

**踩坑现象**：加了 `extend` 后，后续所有镜头画面都比语音晚 1.15s。

**根因**：原实现 `cut_end = next.start + extend` **且**把后续 `start` 全部 `+= extend`，
这假设「下一镜 start 紧贴本镜 cut_end」。但用带停顿配音
（`vo_with_pause`：镜1 末字 3.64s → 镜2 首字 4.79s，中间本来就有 1.15s 空档）时，
目标只是「让画面填满这段已有空档」，而原实现又额外推了 1.15s ⇒ 双重延长。

**现实现**：

```python
_new_cut = min(_vo_end + extend, _old_next)   # 不越过下一镜语音起点
_grow = max(0.0, _new_cut - _old_next)       # 只有超出部分才顺延后续
```

日志会明确打印「空档已够用，不顺延后续」。

**用法**：`extend` 应等于「下一镜首字 − 本镜末字」这段**已有空档**，
而不是额外再加的量。配合 `vo_with_pause.mp3` 使用。

## 排查手册：成片开头没声音 / 音画错位

| 现象 | 检查 |
|---|---|
| 样片有音效、成片没有 | 镜位有没有写 `own_audio: true`；素材是否真有音轨 |
| 双重人声 | `own_audio` 区间内全局 vo 是否已静音（渲染日志会打印） |
| 开头整体右移 0.2s | 接入点是否用了 `timeline.start` 而非素材 0s |
| 后续画面比语音晚 | `extend` 是否与配音已有停顿重复计算 |
| 镜位闪屏（<1s） | `shot_plan.py --config` 抓 ❌；多为某句文案本身太短 |

**验证音频是否真进成片**（别只信渲染成功）：

```bash
# 渲染器会把滤镜链写进 filter_debug.txt
grep -o '\[0:a\][^;]*\[own0\]' filter_debug.txt      # 自带音轨链在不在
grep -o '\[23:a\][^;]*\[vo0\]'  filter_debug.txt      # 全局 vo 静音区间
```

再看成片包络，卷播段应有明显音效垫底（rms 0.2~0.3），
定格处（咚）应有单点峰值。

### ★★★「音效怎么没有了」的头号根因：卷播素材**根本没混音**

**症状**：样片 `片头卷播_X.mp4` 里有滚动音效和定格咚，接进成片后一个都不响。

**实测根因（2026-10-06 肌酸B 条）**：那个「带音轨」的 mp4 **只有视频轨**——
```bash
ffprobe -v error -show_entries stream=index,codec_type -of csv=p=0 片头卷播_B_定格咚.mp4
# → 只有 0,video⇒渲染器 _probe_has_audio() 返回 False
#⇒ 打印「⚠️ 写了 own_audio 但…无音轨 → 忽略」，音效全部丢失
```
`own_audio:true` 写得再对也救不回来——**必须先确认素材本身有音轨**。

**修法：渲染卷播画面后，另跑一步把音效+配音混成带音轨的 mp4**（见下方脚本）。
验收：`ffprobe` 必须看到 `index=1 / codec_type=audio`。

## ★★★钩子整句走卷播时，**定格点定在「价格钩子」末字**，不是产品名

> 灿爹：「白框最后定格应该刚刚框住最后的图才对」（2026-10-07 05:20）

### 定格该落在哪 —— 这是最容易搞错的一处

钩子句结构：`【价格钩子】+ 逗号 + 【今天我们讲，XX】`

|❌ 错的落点 | ✅ 对的落点 |
|---|---|
| 定格在产品名（肌酸）起音 | **定格在价格钩子末字**（健身成本高）落音后 0.07s |
| 白框在「肌酸」才框住主图 ⇒ 前面该停住时还在滚 | 白框在钩子说完那一刻就框住主图，**后半句在定格画面上念完** |

**逻辑**：滚播只为把「价格」这句的视觉张力做满；产品名是**落点**，
应该在画面已经定住之后才说出来 —— 这样「今天我们讲，肌酸」是**配定格画面**的，
而不是配一个还在滚的画面。

**实测（B 条钩子 29 字，1.35 倍速）**：
```

  健2.14  身2.24  成2.35  本2.53  高2.63 ←价格钩子末字
  今2.74  天2.84  我3.02  们3.13  讲3.23← 这段落在定格画面上
  肌3.34  酸3.52
--focus-at = 2.70   ← 「高」落音 2.63 + 0.07
--dur      = 3.70   ← 末字 3.60 + 0.10（不许再拖）
```
| 参数 | 取法 |
|---|---|
| `--focus-at` | **价格钩子末字落音 + 0.06~0.08s**（不是产品名！） |
| `--dur` | 末字时刻 + 0.10（**不许**再往后拖，拖了就是空转） |
| `cover_until` | `= --dur + 0.02`，别多给 |
| 卡列张数 | `≥ 实际滚过卡数 × 1.5`；3.7s 滚 6 张 → 给 16~18 张 |
| 定格咚 | 落在 `focus-at`，同一帧 |

## ★★卷播吃掉整句钩子 + 紧跟科普段（2026-10-06灿爹「整段全部走卷播」）

### 坑1：`extend` 会被「下一镜首字」卡死

`extend` 的语义是「画面填满本镜末字到下一镜首字的**已有空档**」，
所以 `cut_end = min(末字+extend, 下一镜start)`。
卷播要吃掉后面镜次时，下一镜首字就在很前面 ⇒ 卷播只拿到 3.87s 画面，后面全被切走。

**修法（已落地）**：给prod 镜加 `cover_until` 字段，显式声明画面盖到哪一秒。
```python
# build_ad_video.py 2.6b 段（extend 循环之前）
_COVER = [float(pp.get("cover_until", 0.0) or 0.0) for pp in phrases]
# cut_end = max(cover_until, 末字)；顶开下一镜的部分才顺延后续
```
⚠️ 后面那段的 `if _EXT[i] > 0:` 要改成 `if _EXT[i] > 0 or _COVER[i] > 0:`。

### 坑2：被吃掉的镜次，其**文本必须并进卷播镜的 text**

卷播占住 0→6.90s 后，原来镜2/镜3 的配音仍在全局 vo 里，

灿爹「轮播画面中不要出现任何重点字/大字强调」「卷播片段内不再添加额外音效或转场音效」：

删掉 2 个镜后，**`keywords`/`product_cards` 的 phrase 是 1-based要 −2，
`swing_shots` 是 0-based 同样 −2**，别混。

### 坑4：卡数要跟着时长加

卷播从 4.4s 延到 6.84s，滚动量从 ~6 张涨到 11 张 ⇒ 卡列从 16 张补到 **33 张**，
否则同一张卡会连着出现两次，观感「抖动」。判据：
`所需卡数 ≥ 实际滚过卡数 × 1.5`。

### 坑5：语速加快后必须重建 token

只重录第 1 段（`seg_01_fast`），其余段沿用，**不能整条重跑**（8GB机器会 OOM）。
拼接用采样点法最稳（ffmpeg 滤镜图concat 极易踩 `output unconnected`）：
```python

```
whisper `ggml-base` 对长句会识别崩（实测「听到:擔擔擔擔…」），
**优先用「段边界 + 字数比例」造 token**，比逐字识别可靠：
段边界从「拼接时已知的每段起点」+能量法微调首尾（±0.06s 内找 RMS>0.018 的点）。

## ★★★ 5. `--card-sec`：素材数量由配音时长动态计算

**需求（灿爹）**：轮播图片数量必须依据对应配音音频的实际时长动态计算，
使图片总展示时长与配音长度精确对齐，避免提前播完 / 重复轮播 / 与语音节奏脱节。

```math
T_roll  = focus_at（卷播滚动段的配音时长）
n_scroll = round(T_roll / card_sec)         # 需要滚过的张数，card_sec 默认 0.30s/张
卡列     = 素材池[:n_scroll+1] + [主图]      # ★留白 1 张 + 主图压最后
v1       = n_scroll * PITCH / Σf            # 反解速度 ⇒ 位移 = n_scroll×节距
```
```bash
python scripts/opening_banner.py --cards-file cards.txt --out gen/卷播_X_画面.mp4 \
  --dur 5.22 --focus-at 4.31 --v1 190 --no-sub --card-sec 0.30 \
  --hero-src <主图绝对路径>
```
- **边界规则（硬）**：素材池必须 **≥ n_scroll + 1**。
  差一张时（k = N−1）**开场左缘会露出主图右半张 = 同一张出现两次**。
  池子不够 ⇒ **放慢**（`n_scroll = len(pool) - 1`），**绝不循环复用**。
- 每张实占 `T_roll / n_scroll` 秒，与语音节奏一致（本轮 4.30s ÷ 14 = 0.29s/张）。
- 滚动音效拉伸比 >1.5 倍会变味，注意查：本轮 3.68s → 4.31s 仅 1.17 倍 ✓。

### 本文档的cubic 曲线已被实测证伪 ★重要

上面「铁律三」用的 `ease_in_out_cubic`，用相位相关实测渲染后的真实速度：
```
0.00s 2011 px/s → 0.80s 2020 px/s   ★前0.8 秒几乎恒速（甚至微升）
减速比仅 3.3x  ⇒ 这不是「由快到慢」，是「先匀速再急停」
```
**正确解法＝指数减速**（Remotion 版已实现）：
```ts
const K_DECAY = 3.0;                                  // 越大越前快后慢
const sumF = Σ exp(-K_DECAY * i/NF);                  // ★必须数值积分
const v1 = (nScroll * pitch) / sumF;
pos[i] = pos[i-1] + v1 * exp(-K_DECAY * i/NF);
```
实测减速比 **11.1×（理论）→ 19×（成片）**，首帧就是最快。

⚠️ **`1-(1-u)²` / `³` / `⁴` 这类常见缓动曲线用在减速上方向是反的**（越到后面越快，
减速比 0.2–0.3×）。务必实测，别信公式。

## ★★★★ 2026-10-20 NUTREND 轮：大字落位的三条实战结论

> 上面 2026-10-18 的 `150/205` 是「4 字标题 + 人物接近满幅」的解，**不能当通用值直接抄**。
> 本次 3 字「姜黄素」照抄会翻车（中间字被躯干+产品瓶夹死，只露两边），实录如下。

### 1. 字可读性由「中间字宽 vs 主体宽」决定，不由 fontSize 单独决定
主体（躯干+瓶）横跨宽度 W_body，中间字宽 W_mid ≈ fontSize×1.95（1365 图坐标）。
- W_mid / W_body < 1.2 ⇒ 中字基本全被吃掉，只剩两侧字可读（实测 size160 时 80% 被遮）
- W_mid / W_body ≈ 1.5~1.8 ⇒ 头/肩只遮中字中段，上下可辨 = 想要的效果

本次原图主体宽 313px、3 字要 480px 才达标 ⇒ **单靠加字号要 220+，字会顶到画面边**。
正解是**把主体在画面里缩小**（本次 0.80），主体宽降到 250，size 190 即可。
判据：字块总宽 ≈ 画面宽 78~85%、两侧留白 ≥6%。

### 2. 主图人物缩小后，背景必须「彻底无主体痕迹」，`prepare_cutout.py` 不够
`prepare_cutout.py` 的邻域扩散在**暗背景 + 大主体**上会留一圈人形绿影；主体一缩小就暴露。
本轮有效做法（`hero_layers/` 里现成产物可复用）：
1. 归一化卷积大核（金字塔 1/8 尺度 sigma≈14）先出一版平滑底；
2. 再用「垂直高次渐变 + 中心径向光晕」低阶基函数最小二乘拟合（残差中位 4~8）；
3. 用 `MORPH_TOPHAT`（椭圆核 11px，阈值 18）从原图提光尘，只在主体区外回贴。
⇒ 得到纯渐变 + 原光尘的无痕底。**验收：把 bg+fg 合回去，与原图均值差应 < 1**（本轮 0.68）。

### 3. `hero.jpg` 必须 = `hero_bg` + `hero_fg` 的合成图
卡列滚动终点停的是 `hero.jpg`（原图），点击后才换成 HeroCard 三层。
两张不是同一张 ↯ 点击瞬间人物会**突然缩一圈**（本轮实测跳变明显）。
⇒ 改完分层图后，**同步重生成 `cards_dir/hero.jpg` = composite(hero_bg, hero_fg)**。

### 4. 老工程里的 `MarqueeClickD.tsx` 可能是陈稿（写死参数）
本轮项目骨架从旧工程复制，组件里是 `labelTop={16} labelSize={132}` + 压暗层 `zIndex: 900`：
- 前者让 pipeline 注入的 `hero_label_size/top` **静默失效**（永远 16/132）
- 后者让大字被 55% 压暗层盖成暗金（2026-10-15 已修过的坑在旧副本里复活）

**开工自检**（30 秒，别等渲完才发现）：
```bash

```
命中 ⇒ 用技能 `assets/remotion_templates/components/MarqueeClickD.tsx` 覆盖，或按下面两处改成透传：
`HeroCard` 收 `labelTop/labelSize` 且赋默认值；`SlideLabel labelTop={labelTop}`；压暗层 900→750。
